Kế hoạch bên dưới giữ sáu phần và ngôn ngữ kỹ thuật của bản gốc, bổ sung các điều kiện nghiệm thu, mốc lịch cụ thể, thiết kế thí nghiệm và dẫn chứng mã nguồn. Các ngưỡng hiệu quả và hiệu năng đều là mục tiêu đề xuất, chưa phải kết quả đạt được.

1 Project Direction and Architecture
1 1 Objective
EdgeFlow AI will test whether adaptive signal timing reduces vehicle delay and prevents queue spillback in a small connected road network. The system represents roads and movements in a directed graph, obtains traffic observations from SUMO or cameras, and executes decisions through a timed actuator. A successful demonstration requires measured traffic outcomes, learned perception running on embedded hardware, and a physical signal prototype. Red signals remain necessary; the objective is to allocate green time more effectively under explicit constraints.
Represent intersections, approaches and road segments using a canonical directed topology.
Use measured queue, flow, speed and occupancy with documented units, observation windows and uncertainty. Missing measurements must remain missing; they must not be replaced with plausible traffic values.
Keep the present queue-sum controller as the MaxQueue baseline. Implement a movement-based MaxPressure baseline and an EdgeFlow candidate that considers downstream storage and observation quality. Keep RL, PressLight and MARL as extensions.
Support SUMO and vision observations through common semantics. Select one authoritative source for each node and run; never mix synthetic and measured streams silently.
Use one abstract ControlCommand for simulation and physical actuation. Device configuration owns mandatory safety timing; an optimizer cannot shorten it.
Use Docker Compose microservices for the software stack and reproducible integration testing.
Architecture invariant: policy code consumes normalized state and does not branch on the sensor or simulator type. Each actuator owns signal sequencing and reports actual execution. Common contracts define identifiers, units and validity.
1 2 Logical architecture and deployment
The research path closes a loop through SUMO, telemetry, control and a SimulationActuator. The physical path closes a loop through a camera, embedded perception, control and local signal nodes. MQTT carries observations, requests and applied states; API and dashboard display those states and experiment results. A recorded road video can validate perception, but changing a signal cannot change the recorded traffic. Label that mode as replay rather than a traffic-control experiment.

2 Module Work Packages
Work should be assigned by module. Team members can redistribute modules without changing the architecture, provided module boundaries and shared contracts remain intact.
A Contracts
Purpose: Common definitions of messages, topology, movement mapping and provenance. Keep all additions in contracts/ and share one SDK across services.
Extend the three existing schemas with run ID, source mode, source ID, sequence, capture time, validity and applied signal state. Add graph-state, metrics, health and experiment schemas only as their consumers are implemented.
Use four_intersection_v1 first. Define lane-to-approach, incoming-to-outgoing movement, legal phases, turn ratios, storage capacities and exact SUMO connection mappings.
Generate Python and TypeScript types or use a common validated SDK until generation is ready. JSON shape validation must be supplemented by node, phase and movement membership checks.
Provide golden fixtures for valid, stale, missing, duplicate and out-of-order messages. Reject negative counts, impossible durations and unknown topology IDs.
Definition of done: each producer and consumer passes the same valid and invalid fixtures; source substitution preserves measurement meaning as well as JSON structure.
B MQTT Infrastructure
Purpose: Mosquitto-based real-time event transport and Docker network configuration.
Configure a local broker, explicit readiness checks and reconnect behavior. Apply per-client publish permissions for commands; keep the competition system on a controlled local network.
Namespace runs and prevent multiple producers or controllers from owning one node. Use message IDs and sequence numbers for deduplication and command expiry; avoid retained executable commands.
Run a real MQTT test that injects telemetry and observes a command, timed actuation, acknowledgement and API state. The existing direct-import smoke test is a component test.
Definition of done: loss and restoration of the broker cannot cause conflicting green outputs, stale command execution or silent substitution of measurements.
C Simulator
Purpose: Verified SUMO test network, explicit demand generation and raw vehicle-level output. Treat it as a calibrated simulation only to the extent supported by data.
Verify the four-intersection network and all controlled links. Freeze network and route files after validation; do not regenerate the network silently at every startup.
Implement separate demand files and incident events for Balanced, Directional Surge and Downstream Congestion. Scenario names alone must never determine an improvement.
Use halting counts for the declared queue definition, observed crossing counts for flow, and normalized occupancy. SUMO edge occupancy is expressed in percent; convert it to a ratio. Edge vehicle count is not a crossing flow. [R5]
Let SimulationActuator apply actual green, yellow and all-red states. Read back the applied SUMO state. A requested phase or an internal cached value is not proof of execution.
Export tripinfo, scheduled departures, arrivals, unfinished vehicles, queue time series, signal states and incidents. Evaluation must stop on a SUMO failure; synthetic fallback is allowed only in an explicitly marked developer mode.
Definition of done: each scenario changes traffic demand or downstream capacity as intended; run seed reaches the simulator; all actuation and metrics use simulation time.
D Graph Control
Purpose: A validated network-state snapshot and interchangeable controllers. The present message callback uses one node payload and does not yet establish network-level downstream reasoning.
Maintain a time-aligned snapshot of upstream queues, downstream queues and receiving capacity. Record observation age and coverage; do not treat absent approaches as empty.
Implement tuned Fixed-Time, actuated control, MaxQueue, reference MaxPressure and the EdgeFlow candidate behind one policy interface.
Request hold or a legal next phase at a fixed decision interval. Read applied state from the actuator. Device timing constraints, maximum red handling and failover remain authoritative outside the optimizer.
Record the selected phase, candidate scores, blocked movements, data quality, decision time and reason. A tie should retain the current legal phase where appropriate.
Start any RL work only after the non-learning comparison and embedded demonstration pass their gates. Compare it on unseen demand and report training cost and failure cases.
Definition of done: a downstream blockage can change an upstream decision, while changing telemetry publication frequency does not change a Fixed-Time schedule.
E Vision
Purpose: Camera/video perception adapter that emits the same traffic-state semantics as the simulator.
Keep file and webcam adapters. Add the Pi camera or available USB camera path with capture timestamps, correct video-time handling and explicit EOF or disconnection status.
Run a learned vehicle detector on Pi, assign persistent track IDs and calibrate per-camera ROIs. Keep MOG2 only as a development baseline. Select the model using local accuracy and latency measurements.
Estimate stopped queue from motion over time near the stop line; count unique track crossings for flow; report speed in m/s only after calibration. Bounding-box area occupancy is an image proxy and must not be silently equated with road storage occupancy.
Create a per-camera and per-node mapping. The current single ROI setup for the first node must not be reused for every node. Camera failure produces missing data and an alert, never a queue of 2 with confidence 0.90.
Definition of done: embedded inference works on held-out clips and a live camera; detection of stationary vehicles is checked; queue error and end-to-end age satisfy the declared limits.
F Actuator
Purpose: Safe signal execution independent of optimization logic.
Implement a timed SimulationActuator and a physical low-voltage signal adapter in parallel. Target two MCU nodes with local watchdog and fallback schedules; preserve the same abstract command interface.
Enforce GREEN, YELLOW, ALL_RED and next GREEN across actual time steps. Keep a pending command; return ACCEPTED first and APPLIED only after the output state has been applied.
Validate legal node and phase, configured minimum and maximum green, command sequence and expiry. Complete safe clearance on timeout; restart in a defined state and reject replayed commands.
Definition of done: measured output traces prove clearance intervals, no conflicting greens, correct recovery and bounded response to communication loss. Software status alone is insufficient.
G API Persistence
Purpose: System control plane, experiment records, historical querying and dashboard bridge.
Add network-state, experiment lifecycle and controller-configuration endpoints. Validate changes and expose pending, accepted, applied and rejected states.
Use SQLite for a run index and metadata when implemented; keep raw experiment files immutable and reference them by ID and hash. Assign one writer for each record type.
Subscribe to real MQTT state and serve WebSocket updates. Health reports must reflect broker connection, telemetry freshness and backend status.
Definition of done: selecting a controller changes the backend configuration and produces a matching execution record; users can retrieve the run manifest and raw results.
H Dashboard
Purpose: IOC-style visualization for traffic state, system health and benchmark comparison.
Retain the topology map. Replace simulated React state with actual observations and read-back signal states; show NO DATA when observations are unavailable.
Show source mode, experiment ID, measurement age, applied phase, queues, downstream blockage and the reason for the last decision.
Generate benchmark charts exclusively from eligible run artifacts. Show sample count, baseline, units and interval estimates; separate live data, replay and synthetic demonstrations.
Definition of done: an observer can trace every KPI to a run and every displayed signal change to an actuator event. Configuration and manual controls show success only after backend acknowledgement.
I Experiment Runner
Purpose: Reproducible benchmark orchestration and artifact generation.
The manifest must configure and reset the actual simulator, controller and actuator; record their accepted configuration and readiness before starting measurement.
Execute paired controller runs with identical frozen demand and seeds. Disable mock generation in evaluation; fail when no valid samples, no trips, the wrong backend or an incorrect controller is detected.
Capture raw simulator output, signal events, configuration, code and model hashes, environment, metrics and validity status. Compare only eligible runs; retain failed runs and reasons.
Definition of done: a clean run reproduces a scenario and its reported metrics; changing a scenario or seed changes the intended input, not just manifest labels.
J Testing CI Agent Guardrails
Purpose: Cross-module validation, Docker smoke tests and coding-agent safety rules.
Keep unit and contract tests, and add behavioral tests for clocks, clearance, maximum green, expiry, wrong mappings, metric counting and forbidden fallback.
Validate producer/consumer contracts in CI.
Maintain AGENTS.md, architecture decision records and allowed-path task patterns for coding agents.
Require an actual Docker and MQTT closed-loop smoke test before release. Mark it skipped or failed when its dependencies are unavailable; do not substitute direct function calls.
Definition of done: evidence covers observed behavior, including injected failures. Passing schema tests does not prove traffic safety, inference accuracy or performance improvement.
K Embedded perception and physical validation
Collect a small, documented local dataset before choosing or tuning a model. Target 6 to 10 short clips spanning low and high queues, vehicle overlap and at least two lighting conditions. Label at least 300 sampled frames and 10 one-minute counting windows as an initial dataset target. Split by recording session or camera view, not neighboring video frames. Lock the test split before tuning. Record data rights, class definitions, annotator agreement and blind spots.
Treat model cars and road vehicles as different domains. A pretrained road detector may fail on the tabletop. Use separate held-out tabletop data if fine-tuning is needed, and validate real-road clips separately. Mixed motorcycle and car traffic should be a final-stage sensitivity study with explicit vehicle sizes and behavior assumptions, not a claim of city calibration.
Benchmark one existing small detector first, including the YOLO11n option in the BOM. Compare its supported embedded runtime with an NCNN export if useful; current vendor guidance supports Raspberry Pi deployment, but published FPS cannot be assumed for this camera and pipeline. Record model version and export precision, and verify any quantization accuracy loss. [R8]
Physical deliverables include schematic, MCU pin and signal map, LED drivers, current limiting, protected low-voltage power, enclosure, cable labels and a safe-stop input. Test boot, brownout or restart, camera unplug, network outage and recovery. A one-channel relay does not demonstrate compatibility with a real traffic cabinet. Public-road control requires a separate engineering and authorization process; this plan covers simulation and a laboratory prototype.

3 6 Traffic measurement definitions
Quantity
Required meaning and measurement
Queue
SUMO halting count uses its documented speed threshold. Vision uses a declared calibrated stop threshold and dwell time. Report both definitions and their agreement. [R5]
Flow
Unique vehicles crossing a named boundary divided by the observation window in seconds. Do not divide the number currently on an edge by one second.
Network throughput
Distinct vehicles completing or crossing the declared network exits per measurement second. Never sum the same vehicle at successive intersections.
Delay and travel time
Use per-vehicle waitingTime, timeLoss, duration and departDelay, with a declared cohort and completion rate. Queue divided by flow is not the primary delay estimator for changing traffic. [R6]
Occupancy and storage
Convert the SUMO occupancy percentage to ratio. Keep image area, detector time occupancy and storage utilization as distinct fields; estimate physical receiving space separately.
Stopped vehicles
Count unique stopped vehicle IDs or stop episodes as named. Summing stopped counts at every sample yields vehicle-samples, not unique vehicles.

5 2 Hypotheses and controller definitions
H1: under a directional demand change, adaptive control reduces mean vehicle waiting time relative to a tuned Fixed-Time plan without unacceptable deterioration of tail waiting time. H2: explicit downstream receiving capacity reduces spillback duration relative to reference MaxPressure on a finite-storage network. H3: quality-aware observation handling reduces performance degradation and unnecessary switches under camera errors. Each hypothesis can fail; report unfavorable scenarios.
Policy
Purpose and fair configuration
Tuned Fixed-Time
A real clock-based cycle with green splits and clearance. Tune cycle and splits on training demand only; freeze them for test runs.
Actuated
A practical detector-based green extension or gap-out baseline, with documented detector placement and fixed tuned parameters.
MaxQueue
Preserve and rename the present incoming-queue sum policy. This shows whether downstream information adds value beyond local demand.
Reference MaxPressure
Score served movements using upstream queue minus turning-weighted downstream queues, multiplied by saturation service rates. Use explicit movement mappings and shared timing constraints.
EdgeFlow candidate
Reference pressure with a receiving-space filter, calibrated observation-quality handling and a switching margin. Keep the same legal phases and safety timing as the baselines.
Reference pressure is based on the established back-pressure formulation [R3]. For movement i to j, q is its queue, r describes the next turn distribution, and s is its saturation service rate. Sum movement pressure over the movements served by phase p. Exit movements have zero downstream queue. If vision observes only an approach total, allocate by calibrated turn ratios and label it an estimate; evaluate its error instead of calling it exact movement ground truth.
Pp = (i,j)∈psij (qij − krjk qjk)
Apply the EdgeFlow candidate in this order: validate a fresh state snapshot; calculate reference pressure; exclude movements whose downstream receiving space is insufficient for the minimum permitted discharge horizon; compare eligible phases using a switching margin; enforce minimum green, maximum green and service-age constraints; request the change through the timed actuator. With a shared lane, a blocked turning movement may also block other turns, so do not assume it can be removed independently.
Use an upper estimate of downstream occupancy when uncertainty is material. Missing or stale observations must not become zero queues. Brief moderate uncertainty may retain the last valid estimate with a recorded age; exceeding the declared TTL activates the local fallback. If all receiving links are blocked, use a prevalidated hold or clearance behavior and record any infeasible maximum-red target. A fairness rule must not force green into a known full receiving link.
The candidate is a testable heuristic inspired by finite-capacity pressure control, not a new stability theorem. Identify its free parameters, tune them on a separate set and freeze them. All policies share the actuator, legal phase set, minimum and maximum green, clearance and mandatory stale-data failover. Adaptive policies may not gain an unfair advantage by skipping lost time.

Trip cohort: vehicles with scheduled departures inside the measurement window. Track their intended and actual departure, waitingTime, timeLoss, duration and completion. Report unfinished and not-yet-inserted vehicles, backlog, arrivals and departure delay for every policy. SUMO tripinfo omits unfinished vehicles by default, so enable unfinished output and reconcile against the scheduled demand. [R6]
Report completed-cohort mean and P95 waiting time with completion coverage. Do not rank policies by a completed-only mean when completion differs materially or is below the proposed 99 percent target. In those cases lead with fixed-horizon total waiting vehicle-seconds, exit throughput, remaining vehicles and insertion delay; label partial trip statistics as censored. A controller must not appear efficient merely because heavily delayed vehicles never completed.
Report average and maximum queue over time, spillback duration under a declared storage threshold, stop episodes, network exit throughput, P95 delay by approach and signal switches per hour. At low demand, all policies may pass the same number of vehicles; a delay improvement need not produce a throughput gain. Retain each scenario separately and never average unrelated network sizes without weights. This links throughput, access equity and reliability to separate validation measures. [R9]
Use the seed as the independent replicate. Calculate paired differences between EdgeFlow and each baseline, show all five differences and a 95 percent interval on their mean; a paired t interval with four degrees of freedom is exploratory at this sample size. Do not treat one-second telemetry samples as independent runs. Use ten or more seeds for the final where feasible, and emphasize effect size, interval width and scenario consistency rather than a single percentage.
Proposed performance target: at least 15 percent lower mean waiting time than tuned Fixed-Time on the surge scenario, while P95 waiting does not worsen by more than 10 percent and throughput does not materially decrease. Also report comparison with actuated control and reference MaxPressure even if EdgeFlow loses. These are decision targets, not promised improvements. If results fail, retain the negative result and diagnose demand, perception, mapping or algorithm effects.

Appendix A Code evidence and prioritized repairs
All paths below are relative to vedc-traffic-flow/ in the supplied ZIP. P0 items affect validity or actual operation and precede benchmark publication. P1 items strengthen research scope and reproducibility. These are source-level findings unless a separate probe is explicitly described.
A1 P0 Evaluation output is not yet research evidence
services/experiment-runner/runner.py, run and _generate_mock_sample: fallback generation is enabled by default. It uses different random queue and flow ranges according to whether the controller name is max_pressure. In fallback-only operation the first generated sample makes the no-samples condition false, so later loop iterations do not continue generating samples. The runner subscribes and collects, but does not configure or reset the live simulator and controller. A manifest label therefore does not establish which policy or scenario ran.
services/experiment-runner/metrics_collector.py, compute_summary: waiting time is approximated from average queue divided by average reported flow; throughput is averaged across telemetry messages; stopped counts are summed over samples. The two aggregate files under artifacts/ report 12 and 48 runs respectively, and the JSON repeats identical values for all three scenarios. No per-run traces accompany them in this ZIP. Preserve these as unverified development artifacts and rerun the study; their provenance cannot be inferred from the summaries alone.
A2 P0 Control timing and safety are incomplete
services/graph-control/controller.py, FixedTimeController.compute_command: the phase counter increments on every invocation, independent of elapsed time. cycle_time_s appears as a command maximum rather than a schedule. A same-timestamp probe produced EW, NS, EW. services/actuator/state_machine.py, process_command: YELLOW, ALL_RED and GREEN assignments execute consecutively in one call, and max_green_s is not enforced. The ACK says APPLIED immediately. Add a clock-driven state machine, configuration authority, topology checks, expiry and actual output read-back.
A3 P0 Simulator measurements and mappings need repair
services/simulator/sumo_engine.py: getLastStepVehicleNumber is divided by 1.0 and named flow; occupancy is clamped as if already a ratio; the timestamp is simulation time multiplied by 1000. setPhase maps to a green phase directly and cached phase state is used in telemetry. services/simulator/traffic_engine.py silently falls back to synthetic dynamics, whose node queues do not propagate vehicles along the graph. These paths cannot support an unqualified network-throughput claim. [R5, R7]
src/graph/sumo_converter.py, parse_net_xml: green signal characters are mapped to sorted approaches with index modulo the number of approaches. The correct mapping uses controlled connections and linkIndex, not a modulo relationship. Validate every movement against the actual .net.xml. The Cologne routes file is empty, and hcm_realworld_v1 has no corresponding SUMO config in the supplied tree. Exclude these from traffic-effect claims until independently completed. [R7]
A4 P0 Vision and interface values must reflect observations
services/vision/perception_engine.py uses background subtraction and contours; metrics_extractor.py defines queue as box count, flow as queue multiplied by 0.08 and speed as an occupancy formula. main.py sets ROIs only for the first node, loops over all nodes and supplies plausible traffic when a frame fails. There is no trained vehicle detector or persistent tracking implementation in these files. Replace these placeholders, measure stationary-queue accuracy and preserve invalid observations.
services/dashboard/src/pages/NetworkOverview.jsx and IntersectionDetail.jsx generate random traffic values. PerformanceAnalytics.jsx holds fixed results. ControlPanel.jsx sets success messages without sending policy or override requests to a backend. services/api/main.py provides topology and map endpoints, without the claimed telemetry bridge, experiment persistence and live control implementation. Retain the interface layout while connecting genuine state and acknowledgement.
A5 P1 Network reasoning and test coverage
services/graph-control/controller.py, MaxPressureController: phase score is the sum of queues on its incoming approaches; no downstream queue, saturation flow or turn weighting enters the decision. graph-control/main.py handles each node message directly without maintaining a network snapshot or checking telemetry freshness. Keep the current algorithm as MaxQueue and make downstream state explicit for the reference pressure policy.
src/graph/build_camera_graph.py and build_camera_graph_delaunay.py build proximity and OSRM route graphs between camera locations. These do not by themselves supply legal signal movements, link storage, turn proportions or traffic demand. tests/integration/test_smoke.py calls classes directly with the synthetic engine; existing tests often verify shapes and immediate transitions. Add behavioral tests without treating the number of tests as evidence of controller correctness.
A6 Verification limits and archive identity
The review performed text and source inspection plus isolated controller and mock-function probes. It did not run the full container stack, SUMO, a camera or MCU hardware. make contracts and make test both failed at tool availability with No module named pytest, rather than reporting product-test failures. The isolated mock probe verifies the biased generation mechanism only; it does not reproduce or authenticate the supplied aggregate report.
